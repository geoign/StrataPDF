# StrataPDF の設計

## スレッド構成

MuPDF の `fz_document` はスレッドセーフではない。ただし、ページから作った表示リスト
（`fz_display_list`）は、複数のスレッドから同時に描画できる。StrataPDF はこの性質を使い、
スレッドを次のように分けている。

```
UI スレッド (egui)
  │ 毎フレーム「足りないタイル」の一覧を優先度順に提示
  ▼
RenderPool ── 描画ワーカー × (論理コア数 − 2)
  │ 表示リストを要求（同期）       │ タイルを RGBA で返す
  ▼                                 ▼
文書スレッド（1ファイルに1本）    UI がテクスチャ化して LRU で保持
  表示リスト・テキスト・リンク・アウトラインを生成し、LRU でキャッシュ

寸法走査スレッド / 検索スレッド
  それぞれ同じファイルの別インスタンスを開く。文書スレッドを塞がない。
```

- **文書スレッド**（`strata-core/src/doc.rs`）は、ページの読み込みと表示リスト化だけを行う。
  重い処理である画素化は描画ワーカーが並列に担う。
- **ページ寸法**は、開いた直後に1ページ目の寸法で全ページを仮置きする。別スレッドが実寸を順に
  埋め、UI は `Document::revision()` の変化を見てレイアウトし直す。数千ページの文書でも、
  開いた瞬間から表示を始められる。
- **全文検索**も別インスタンス上で走る。キャンセルはフラグで行う。

## タイル描画

- 拡大率は 1/4 オクターブ刻みの「レベル」に量子化する（`scale = 2^(level/4)` px/pt）。
  要求された倍率以上で最小のレベルで描き、GPU 側で縮小する。
- タイルは 512×512 px。ページの右端と下端のタイルは小さい。
- UI は毎フレーム、ビューごとに「画面内で足りないタイル」を優先度順に `set_wanted` する。
  ワーカーは全ビューの一覧から最も優先度の高い未着手タイルを取る。画面外に出たタイルは一覧から
  消えるので、取り消し処理そのものが要らない。
- ズーム中は、キャッシュ済みの別レベルのタイルを拡大・縮小して仮表示する。ページ全体の
  低解像度版（サムネイル用のレベル）を常に先に要求するので、白いページは一瞬しか出ない。

## フォント解決

非埋め込みフォントは `strata-core/src/fonts.rs` の独自ローダーで解決する。起動時に Windows の
フォントフォルダを一度だけ走査し、PostScript 名・フル名・ファミリー名（日本語名を含む全言語）で
索引を作る。`Ryumin-Light` や `GothicBBB-Medium` のような、Windows に存在しない和文の汎用名は、
游明朝か游ゴシックに割り当てる。

`mupdf` クレート標準の `font-kit` ローダーは、未知のフォント1つごとに全フォントを列挙し直す
（Windows で約1秒かかる）。そのため機能フラグ `system-fonts` を外してある。

## 権限フラグの扱い

所有者パスワードだけの PDF は、パスワードなしでそのまま開く。利用者パスワードの PDF は、
パスワードの入力後に開く。どちらの場合も権限フラグ（印刷・コピー・編集の禁止）は参照しない。
保存時に暗号を外す機能は M4 で入れる。

## エンジン依存の境界

MuPDF の型（`mupdf::*`）を直接使うのは `strata-core` の中だけに限る。アプリ側には、
所有権を持つ Rust の型（`PageText`、`RectF`、`QuadF`、`RenderedTile` など）だけを渡す。
エンジンを PDFium に差し替える場合、書き換えの対象は `strata-core` に閉じる。ただし PDFium は
描画がプロセス全体で1スレッドに制限されるため、並列描画の設計は維持できない。

## リフロー（Markdown / HTML 表示）

`strata-core/src/reflow/` が固定レイアウトのページを線形の文書（見出し・段落・リスト・図・表・
数式・脚注）に組み直す。処理は3段。

1. **抽出**：ページごとに MuPDF の構造化テキストを取り、`rich.rs` で書式付きの独自構造に写す。
   1文字ずつ縦に積まれた行（Chromium や Word が出力する縦書き）は、ここで縦の1行にまとめ直す。
   文書全体の統計（本文の文字サイズ、繰り返し現れる柱・ノンブル、縦書きか否か）もここで集める。
2. **ページ単位の整形**：柱とノンブルを除き、画像とベクタ図形の塊を図にまとめ、XY-cut
   （`order.rs`）で読み順を決める。横書きは段間を先に、縦書きは段（上下の組）を先に切る。
   各要素を見出し・キャプション・表・数式・リスト・脚注・段落に分類する。
3. **連結**：段やページの境目で切れた段落をつなぐ。図・表・脚注は割り込みとみなして飛ばす。
   縦書きは字下げと前の列の終わり方で段落の境目を判定する。

テキスト層が使えないページ（スキャン、ToUnicode のないフォント）はページ画像として出し、
「OCR が必要」と明示する。M3 の OCR がここを置き換える。数式と表は現状では画像で出す。
数式は M3 で LaTeX に置き換える（`Node::Formula::latex`）。

表示は WebView2（wry）の子ウィンドウをタブの本文領域に重ねて行う。HTML と画像は独自
プロトコル `http://strata.doc/` でメモリから配る（文字列で渡すと 2MB の上限がある）。
ページ番号の目印を押すと PDF 表示の該当ページへ戻る。WebView がキーボードを持っている間も
主要なショートカットは JS 経由でアプリに届く。

ウィンドウを出さない変換は `crates/strata-cli`（配置名 `StrataPDF-cli.exe`）が担う。
GUI と同じく `Document::reflow` と `reflow::output` を呼ぶだけで、egui と WebView2 には依存しない。
GUI の exe は Windows サブシステムで、PowerShell と cmd が終了を待たないため、別のコンソール用 exe にした。
`StrataPDF.exe --headless` と `--help` は呼び出し元のコンソールに接続してから CLI を起動する（`strata-app/src/headless.rs`）。
使い方は `docs/CLI.md`。

## OCR と数式認識

`strata-ocr` クレートが推論を担う。ONNX Runtime（`ort`）を使い、GPU は DirectML で動かす。
DirectML は DirectX 12 対応の GPU なら追加インストールなしで動く。CUDA 版は cuDNN などの
DLL 一式を要するため採らない。

- **OCR**：NDLOCR-Lite（国立国会図書館、CC BY 4.0）の Rust 移植（`ndl.rs`）。DEIM でレイアウトと
  行を検出し、PARSeq（30/50/100 文字の3段）で行を読む。縦の行は 90° 回して読む。
  前処理（OpenCV 互換の双線形縮小、整数座標での切り出し）を本家に合わせ、同梱サンプルで
  本家 Python 版と文字一致率 98〜99% を確認した。DEIM は DirectML だと検出が 0 件になるため
  常に CPU で動かす。
- **数式**：Pix2Text MFR 1.5（MIT、DeiT エンコーダと TrOCR デコーダ）。貪欲法で復号し、
  バイトレベル BPE を自前で文字列に戻す。デコーダの入力長が毎ステップ伸びるため DirectML では
  グラフの組み直しが起き 5〜10 倍遅い。常に CPU で動かす。LaTeX は `math-core` で MathML Core に
  変換し、WebView2（Chromium）の標準機能で描く。
- **モデル**：初回使用時に確認ダイアログを出してダウンロードする（`models.rs`）。取得元は
  コミットやリビジョンを固定した URL で、SHA-256 を検証する。`%LOCALAPPDATA%\StrataPDF\data\models\models.json`
  を置くと、コードを変えずに一覧を差し替えられる。

`strata-core/src/ocr.rs` がアプリ側との橋渡しをする。

- ページを 150dpi で描画して OCR し、座標を PDF のページ空間（pt）に写す。
- 結果は文書ごとに保持し、`%LOCALAPPDATA%\StrataPDF\data\ocr\` に JSON Lines で追記保存する
  （キーはパス・サイズ・更新時刻）。同じファイルを二度 OCR しない。
- PDF 自身のテキスト層が使えないページに限り、文字選択・コピー・検索・リフローが OCR 結果を使う。
  既存のテキスト層を置き換えるのは、利用者が「スキャンページを OCR し直す」「全ページを OCR」を
  選んだときだけである（`PageOcr::forced`）。
- **既存 OCR の品質判定**（`ocrq.rs`）：他のソフトの OCR 文字が付いたスキャンページが文書の半分以上
  あるとき（半分未満なら、ボーンデジタル論文の全面図版であることが多い）、文書の主な言語で誤認識の割合を推定する。英文は辞書（Webster 第2版の語彙表に屈折・英国綴り・
  複合語の規則を足したもの）にない小文字の語と、記号・数字・大文字が語中に混じった語の割合。
  論文中で繰り返し使われる5文字以上の語は専門語とみなす。和文は JIS 第2水準以降の漢字、
  カタカナ語中の片仮名もどきの漢字（ユニッ卜）、漢字間の孤立したカタカナ、漢字に挟まれた短い英字列の割合。
  英文 4%・和文 1% を超えるとリフロー表示のツールバーで内蔵 OCR による読み直しを勧める。
  しきい値は、画像と照合して誤りを数えた 50 本で決めた（ほぼ完璧な 25 本は1本も該当しない）。
- **検索可能 PDF の書き出し**：OCR 結果を描画モード 3（不可視）のテキスト層として追記する。
  フォントは Adobe-Japan1 の非埋め込み CID フォント（UniJIS-UTF16-H）。縦の行は縦書きフォントを
  使わず、横書きフォントを 90° 回して置く。MuPDF などが縦書きフォントの文字を1字ずつ別の行として
  扱い、行をまたぐ検索ができなくなるためである。既存の描画内容は `q`/`Q` で囲んで状態の漏れを防ぐ。

## 注釈と保存

注釈の編集は文書スレッドが持つ `PdfDocument` に対して行う（`strata-core/src/annot.rs`）。
対応する種類は、ハイライト・下線・取り消し線・波線・矩形・楕円・直線（矢印）・手書き・
テキストボックス・付箋。その他の種類は表示と削除だけができる。座標は MuPDF のページ空間。

- **描画の更新**：編集したページは版番号（`page_rev`）を上げる。版番号はタイルのキーに含まれる
  ため、編集後のページは自動で描き直される。新しい版が届くまでは一つ前の版のタイルを表示する。
- **取り消し**：操作ごとに逆操作を積む（`History`）。MuPDF のジャーナル機能（`pdf_undo`）は
  例外を投げうる C 関数で、Rust 側に安全なラッパーがないため使わない。削除の取り消しで作り直した
  注釈はオブジェクト番号が変わるので、履歴中の参照を付け替える。
- **テキストボックスの日本語**：MuPDF の外観生成が文字の用字系を見て和文フォントを自動で加える。
- **保存**：上書き保存は差分追記（incremental）で、元の暗号を維持する。名前を付けた保存は全体を
  書き直し、既定で暗号を外す（MuPDF の既定は暗号の維持なので明示的に外す）。開いている
  ファイル自体への全体書き直しはできない（読み込み中のため）。
- **未保存の保護**：未保存の変更があるとタブ名に「●」を付ける。タブやウィンドウを閉じるときに
  保存・破棄・取り消しを尋ねる。
