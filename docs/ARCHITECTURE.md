# StrataPDF の設計

## スレッド構成

MuPDF の `fz_document` はスレッドセーフではない。ただし、ページから作った表示リスト
（`fz_display_list`）は、複数のスレッドから同時に描画できる。StrataPDF はこの性質を使い、
スレッドを次のように分けている。

```
UI スレッド (egui)
  │ 毎フレーム「足りないタイル」の一覧を優先度順に提示
  ▼
RenderPool ── 描画ワーカー × (論理コア数 − 2)
  │ 表示リストを要求（同期）       │ タイルを RGBA で返す
  ▼                                 ▼
文書スレッド（1ファイルに1本）    UI がテクスチャ化して LRU で保持
  表示リスト・テキスト・リンク・アウトラインを生成し、LRU でキャッシュ

寸法走査スレッド / 検索スレッド
  それぞれ同じファイルの別インスタンスを開く。文書スレッドを塞がない。
```

- **文書スレッド**（`strata-core/src/doc.rs`）は、ページの読み込みと表示リスト化だけを行う。
  重い処理である画素化は描画ワーカーが並列に担う。
- **ページ寸法**は、開いた直後に1ページ目の寸法で全ページを仮置きする。別スレッドが実寸を順に
  埋め、UI は `Document::revision()` の変化を見てレイアウトし直す。数千ページの文書でも、
  開いた瞬間から表示を始められる。
- **全文検索**も別インスタンス上で走る。キャンセルはフラグで行う。

## タイル描画

- 拡大率は 1/4 オクターブ刻みの「レベル」に量子化する（`scale = 2^(level/4)` px/pt）。
  要求された倍率以上で最小のレベルで描き、GPU 側で縮小する。
- タイルは 512×512 px。ページの右端と下端のタイルは小さい。
- UI は毎フレーム、ビューごとに「画面内で足りないタイル」を優先度順に `set_wanted` する。
  ワーカーは全ビューの一覧から最も優先度の高い未着手タイルを取る。画面外に出たタイルは一覧から
  消えるので、取り消し処理そのものが要らない。
- ズーム中は、キャッシュ済みの別レベルのタイルを拡大・縮小して仮表示する。ページ全体の
  低解像度版（サムネイル用のレベル）を常に先に要求するので、白いページは一瞬しか出ない。

## フォント解決

非埋め込みフォントは `strata-core/src/fonts.rs` の独自ローダーで解決する。起動時に Windows の
フォントフォルダを一度だけ走査し、PostScript 名・フル名・ファミリー名（日本語名を含む全言語）で
索引を作る。`Ryumin-Light` や `GothicBBB-Medium` のような、Windows に存在しない和文の汎用名は、
游明朝か游ゴシックに割り当てる。

`mupdf` クレート標準の `font-kit` ローダーは、未知のフォント1つごとに全フォントを列挙し直す
（Windows で約1秒かかる）。そのため機能フラグ `system-fonts` を外してある。

## 権限フラグの扱い

所有者パスワードだけの PDF は、パスワードなしでそのまま開く。利用者パスワードの PDF は、
パスワードの入力後に開く。どちらの場合も権限フラグ（印刷・コピー・編集の禁止）は参照しない。
保存時に暗号を外す機能は M4 で入れる。

## エンジン依存の境界

MuPDF の型（`mupdf::*`）を直接使うのは `strata-core` の中だけに限る。アプリ側には、
所有権を持つ Rust の型（`PageText`、`RectF`、`QuadF`、`RenderedTile` など）だけを渡す。
エンジンを PDFium に差し替える場合、書き換えの対象は `strata-core` に閉じる。ただし PDFium は
描画がプロセス全体で1スレッドに制限されるため、並列描画の設計は維持できない。

## リフロー（Markdown / HTML 表示）

`strata-core/src/reflow/` が固定レイアウトのページを線形の文書（見出し・段落・リスト・図・表・
数式・脚注）に組み直す。処理は3段。

1. **抽出**：ページごとに MuPDF の構造化テキストを取り、`rich.rs` で書式付きの独自構造に写す。
   1文字ずつ縦に積まれた行（Chromium や Word が出力する縦書き）は、ここで縦の1行にまとめ直す。
   文書全体の統計（本文の文字サイズ、繰り返し現れる柱・ノンブル、縦書きか否か）もここで集める。
2. **ページ単位の整形**：柱とノンブルを除き、画像とベクタ図形の塊を図にまとめ、XY-cut
   （`order.rs`）で読み順を決める。横書きは段間を先に、縦書きは段（上下の組）を先に切る。
   各要素を見出し・キャプション・表・数式・リスト・脚注・段落に分類する。
3. **連結**：段やページの境目で切れた段落をつなぐ。図・表・脚注は割り込みとみなして飛ばす。
   縦書きは字下げと前の列の終わり方で段落の境目を判定する。

テキスト層が使えないページ（スキャン、ToUnicode のないフォント）はページ画像として出し、
「OCR が必要」と明示する。M3 の OCR がここを置き換える。数式と表は現状では画像で出す。
数式は M3 で LaTeX に置き換える（`Node::Formula::latex`）。

表示は WebView2（wry）の子ウィンドウをタブの本文領域に重ねて行う。HTML と画像は独自
プロトコル `http://strata.doc/` でメモリから配る（文字列で渡すと 2MB の上限がある）。
ページ番号の目印を押すと PDF 表示の該当ページへ戻る。WebView がキーボードを持っている間も
主要なショートカットは JS 経由でアプリに届く。
