## 2026-09-29 の追加

- JBIG2 の走査画像を含む PDF が開くと落ちる不具合を修正（共有辞書 JBIG2Globals を複数スレッドで同時に復号するとヒープが壊れる。該当ファイルだけ描画を1スレッドずつにした）
- Space / Shift+Space でスクロール送り・逆送り（PDF 表示とテキスト表示の両方。縦書きのテキスト表示では左右に送る）。
  以前から Space はあったが、Shift+Space も前送りになっていた
- PDF 表示で画像を右クリックして「名前を付けて画像を保存」：埋め込み JPEG はそのまま、それ以外は元の画素数の PNG
  （色空間・デコード配列・ソフトマスクを反映。マスク付きは透過 PNG）
- 見開き表示を縮小すると、画面幅に入るだけ見開きを横に並べる（右綴じでは右から）。幅・全体に合わせるときは従来どおり1見開き
- テキスト表示の文字サイズ（60〜320%、全タブ共通で設定に保存）：ツールバーの A－ / A＋、Ctrl+ホイール、Ctrl+± / Ctrl+0
- テキスト表示からの操作（ページ番号クリック・Ctrl+W など）が次の入力まで処理されなかった不具合を修正
- リフローで図・段・ページの境目に切れた段落をつなぐ（決定論的な規則のみ）：
  片段だけの小見出しで段が交互に並ぶ読み順の修正、図の中の軸ラベル・凡例を図へ吸収、
  段の末尾まで詰まった段落と次の段頭の本文をつなぐ、同じ段で書体の変化により分かれた行をつなぐ、
  フォント名からの太字判定（`.B` など）、"2.1 | Title" 形式の見出し、行番号付き原稿（行番号を除去し行間を広く見る）。
  文の途中で切れた段落の数（`examples/reflow_breaks.rs`）：開発用 5 本 102→48、検証用 3 本 39→27、未見 3 本 684→135

## 0.2 に向けて（2026-09-30）

- リフローに PyMuPDF Layout のレイアウト解析を導入（`crates/strata-core/src/layout.rs`、`crates/strata-ocr/src/layout.rs`）。
  行ごとに見出し・本文・キャプション・図中の文字・柱などを判定し、見出しの判定、柱の除去、図中の文字の吸収、
  種類の混じったブロックの分割に使う。特徴量計算の C コードとモデルは同梱（exe に約 9 MB 増）。
  Python 版の中間値との照合で、行の分類は 99.9% 一致。処理時間は 20 ページの論文で約 1 秒から約 3 秒
- 文の途中で切れた段落の数：開発用 48→42、検証用 27→24、未見 135→116。見出しの取りこぼし・誤検出も大きく減った
  （Carey 2010 は見出し 9→31、図の軸ラベルや著者名の誤検出がほぼ消えた）
- 行番号の除去を余白の列に限定（表の数値の列を消していた）。見出し番号だけの行を同じ行の見出しにつなぐ

## コマンドラインでの変換（2026-10-03）

- `StrataPDF-cli.exe convert`：Markdown と HTML（同時出力可）への書き出しをウィンドウなしで行う。
  OCR（`--ocr`）、数式の LaTeX 化（`--latex`）、ワイルドカード展開、標準出力への出力に対応。
  `StrataPDF.exe --headless` からも呼べる。説明は `docs/CLI.md`、エージェント向けの要約は `AGENTS.md`
- v0.2.2 の後：変換を `StrataPDF.exe --headless` に移し、`StrataPDF-cli.exe` は起動して待つだけの窓口にした
  （61 MB → 約 230 KB。MuPDF・ONNX Runtime・モデルを二重に配らない）

## 公開（2026-09-29）

### 編集（M4 以降）

注釈以外の編集は、すべて `strata-core` に `edit` モジュールを設け、PDF オブジェクトへの操作として実装する。
UI 側には「編集操作」の列挙型だけを見せ、取り消し・やり直しは操作の逆操作の列として持つ。

- [ ] ページ操作：回転・削除・並べ替え・挿入・結合・分割（MuPDF の `PdfDocument::move_page` などで実装できる）
- [x] 画像抽出：元の符号化のまま（JPEG のみ）と PNG 変換の両方（2026-09-29、右クリックから1枚ずつ）
- [ ] 画像の一括書き出し（ページ範囲・文書全体）、JPEG 2000 など JPEG 以外の元データのまま保存
- [ ] 画像の差し替え・削除
- [ ] 注釈の焼き込み（`bake`）
- [ ] 図形・文字の焼き込み（コンテンツストリームへの追記）。和文は Noto Sans JP などをサブセット化して埋め込む
- [ ] 既存テキストの書き換え：元のグリフを消し、新たに埋め込んだフォントで書き直す
- [ ] 墨消し（下層の文字・画像・ベクタを実際に削除する）
- [ ] フォーム入力、署名欄の表示
- [ ] オブジェクトツリーの閲覧と編集（上級者向けインスペクタ）
- [ ] 保存結果の検証：`qpdf --check`、PDFium・pdf.js での再読込

### OCR・数式（M3 以降）

OCR は `OcrEngine` トレイトで抽象化する。M3 ではローカルのエンジンだけを実装する。

- [ ] API 経由のエンジン（HTTP の VLM エンドポイント：自前の llama.cpp / vLLM サーバ、クラウド API）。
      トレイトの実装を1つ足せば済むようにしておく。送信前の確認ダイアログを必須とする
- [ ] Windows 標準 OCR（Windows.Media.Ocr）は見送った。NDLOCR-Lite が縦書きを含めて上回るため。
      モデル未取得でもすぐ使える予備として実装する価値はある
- [ ] PP-OCR 系（多言語）の追加。英語以外の欧文や中国語が主な文書向け
- [ ] 数式領域の検出をレイアウト解析モデルで行う（現在は文字フォントの統計による推定。
      "MultiHead(Q,K,V)=Concat(…)" のようにローマン体の演算子名が多い式を取りこぼす）
- [ ] 行内数式の LaTeX 化（現状は表示数式のみ）
- [ ] より新しい軽量モデルへの差し替え：モデルの一覧はダウンロード用マニフェスト（JSON）で管理し、
      コードを変えずに追加できるようにする
- [ ] 文書レイアウト解析モデル（段組み・表・図の領域検出）によるリフロー品質の向上。`reflow::RegionHint` を入力に取る形で差し込む
- [ ] リフローの段落連結の残り：段頭が大文字で始まる続き（固有名詞など）、表のページの扱い
- [ ] レイアウト解析：表のセル構造モデル（PyMuPDF Layout の table grid）、読み順への利用、縦書きへの対応、
      CNN の GPU（DirectML）実行、mupdf-sys の MuPDF 1.28 化で行分割を Python 版とそろえる
- [ ] 表の構造化（セル単位の HTML / Markdown 表）。現状は画像と生テキスト
- [ ] ルビの保持（`<ruby>` として出力）。現状は除去
- [ ] 縦書きの多段組（上下2段以上）の検証
- [ ] 大きな文書のリフローの並列化（ページ単位で独立なので分割できる）
